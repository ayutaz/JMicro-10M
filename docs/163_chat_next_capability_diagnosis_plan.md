# 今回の失敗から進める次の課題と計画

2026-10-18。[結果162](162_chat_input_structure_sft_results.md)に基づく次の提案。**次は主SFTを増やす前に、二つの最新情報を短い回答へまとめる課題を、同じ10Mモデルが小集合で学べるか調べる。** 今回の4工程を完了した後の計画で、まだデータ著作・新configのfreeze・追加学習は行っていない。

## 優先する課題

| 課題 | 実証された根拠 | 次に分けて調べること |
|---|---|---|
| 二属性の回答 | 公開100の最終20会話は両腕0/20。正しい履歴での先行診断も二属性0/80 | 値を個別に知ることと、二つを回答へ組み合わせること |
| 訂正対象と最新値 | 新DEVに色・人数・場所・人物の旧値への戻りが残る | 一項目だけの変更と、変更しない項目の保持 |
| 質問対象の選択 | 人物を問われて物を返す、午前を問われて午後を返す | 同じ事実から質問に応じて回答対象を変える教師 |
| 未提示情報の扱い | 不足情報での創作、提示済み時刻への「未提示」の返答 | 不足時の質問と、既知時の直接回答の区別 |
| 反復・停止・文字破損 | 同文連続は11→5/20でも最終回答0/20。UTF8破損も残る | 同文フラグに加え、意味の循環・完結・raw bytesを同時に見る |

入力の並べ替えだけの今回条件は閉鎖する。旧条件の教師数延長、よい途中点やdecoderへの差し替えで救済しない。上記を全部同時に直す教材にもせず、最初は「回答対象を選び、最新の二値を出す教師」に絞る。計算や英数字教材の追加は別の比較にする。

## 最初に実行可能にする小集合診断

1. TRAIN専用の64対象を著作する。8組の独立した事実family×記憶/訂正×単属性/二属性×短い/離れた質問で64件。変更前・変更後・変更しない値と、最後の質問の要求対象から答えを検証し、全64の本文を直接確認する。今回の公開100、DEV、実ブラウザーの誤答を教材へ移さない。
2. 教師は自然で完結した32token以内にする。二属性は二つの値と対応を明記し、一属性なら要求された値だけを返す。TRAINの役割順、完全教師マスク、履歴非切断、aliasと独立件数を区別して記録する。64件を繰り返す診断をデータ多様性や汎化の証明とは呼ばない。
3. TRAIN確定後に別の64問を作る。32問は未学習の値、32問は質問表現・配置の変化。さらに16会話×3応答を実生成履歴で評価する。TRAIN64の学習前後128、新しい64、実会話48の計240応答を全て理由付きで確認する。新しい封印TESTは作らない。
4. 元Base/fresh Adam/同10M・seed42・元LR1e-4・BF16/math・元最大shape・greedy32を使う別診断を契約する。教師量は25万、技術600秒・学習1,800秒・評価1,800秒を計画上限とする。これは新しい実測予測ではない。CPU全消費と変更経路の保存再開、全32技術更新の計時から、この枠で成立することを本学習前に確認する。

小集合の学習成立の提案基準は、TRAINの要求値64/64、自然停止64/64、文字破損・役割漏れ・履歴切断0。文法と関連性も別に採点する。TRAINの低NLLだけで合格にしない。未知64では、未学習の値と構造の各32で内容成立24/32以上、実会話の最終16で文脈成立12/16以上を次の主比較を検討する目安として事前固定する。これは能力診断の新しい提案値で、元の品質採用条件を緩めるものではない。

## 結果による分岐

| 小集合の結果 | 次の作業 |
|---|---|
| TRAIN64自体を学べない | label/input/出力対象の整合性と、単属性から二属性に増えたときの失敗を原状態で調査する。閉鎖した32件診断を再実行せず、原因を絞るまで主SFTへ進まない |
| TRAINは学べるが未知値・構造で失敗 | 対象選択や値の組合せの転用が弱い。TRAINと未知入力の対応を調べ、具体的な未回答仮説一つを次契約にする。学習時間だけを増やさない |
| 未知値・構造と実会話の目安を満たす | その教師方針を一つの変更として、新対照と候補を同じ元Baseから学ぶ主SFTを前向きに準備する。小集合重みを主比較の親にしない |

次の主比較を実施する場合は、新しいTRAINを確定してから新DEV80を作り、現在の7評価組と公開100を保持する。全回答・全実履歴・品質差の対応CI・回帰・実ブラウザーを確認する。元の内容56/80、最終文脈15/24、停止/空/反復/UTF8等の条件は維持する。技術600秒・学習各7,200秒・評価10,800秒を計画枠とし、変更後データの実測予測を先に出す。累積ローカルGPU上限なしの既存指示の下でも、各実行には有限の終了条件を置く。

今回見つかったPowerShellのWorker switchとworker変数の衝突は、旧凍結sourceを保全したまま次の別launcherで修理する。元UIの実identity/lockを開始前に確認し、終端で復帰を検証する。

この診断が成功しても、Base全般の意味能力、独立した全pipeline、全文DEV・440・新TEST・正式採用が完了したことにはならない。参考モデルとの差の原因も、語彙や学習履歴等を独立に比較しなければ確定できない。次に確かめる範囲は、同じ10Mが短い二属性回答を学び、未学習の値と質問へ転用できるかである。
