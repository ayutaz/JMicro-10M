## 3. 教材を準備する

### 候補と配合

| 候補 | 役割 | 最初の候補配合 |
|---|---|---:|
| RealPersonaChatの利用可能なTRAIN会話を拡張・選別 | 自然な相づち、日常の話題、複数turnの応答 | 70% |
| llm-jp/magpie-sft-v1.0の短く完結した日本語応答を選別 | 質問への直接回答、必要な確認、Assistantとしての応答 | 30% |

比率は**消費するAssistant本文＋EOT教師tokens**で定義し、会話件数比とは区別する。70/30は準備前の提案で、採用できる実量と内容を確認してから固定する。旧素材・Baseデータに含まれた出典との重複も記録し、初めて接した情報と断定しない。

RealPersonaChatの公式公開版は13,583会話で、元の2,688会話pilotとは量が異なる。ただし全件が新TRAINとして使用可能という意味ではない。プロジェクトの既存保留ID・splitを維持し、評価用会話をTRAINへ移さない。元データは人間同士の雑談で、各発言が正確なAssistant回答とは限らない。[公式説明](https://github.com/nu-dialogue/real-persona-chat)

Magpieの公開ページには日本語の生成された質問応答、生成元情報、Apache-2.0表示がある。長い説明や不適切な内容もあり得るため、無条件に全件投入しない。単発QAから複数turnの記憶を学べるとは主張しない。[公式データセット](https://huggingface.co/datasets/llm-jp/magpie-sft-v1.0)

### 準備の具体的な手順

1. 既存TRAINのmanifest・利用済み会話ID・評価保留IDを先に確認し、追加で必要な公開資料だけrevision/hashを固定する。新しい全Base corpus監査は行わない。
2. 出所・元ID・会話単位のfamilyを保持する。既存DEV/TESTのIDを再割当しない。本文を読む前の入口で、許可したTRAIN側のファイル・IDに限定する。旧混在評価ファイルを全行解析してから除外する方式へ戻さない。
3. 空応答、文字破損、単なる全文復唱、根拠のない個人属性、履歴なしでは解釈できない発言、質問に答えていない教師を除く。自己紹介・引用などの意味を見ず、文字一致だけで一律除外しない。
4. 既存4k Tokenizerで、**完結した応答の本文＋EOTが2〜64教師tokens**の対象を採る。長文を途中で切ってEOTを付けない。必要な履歴を含めcontext1024へ収まらない例は理由付きで除外する。
5. 完全一致・近似重複・同じ元会話の派生窓を追跡する。同じ応答が複数windowへ出た場合は独立な情報として増やさない。話者・会話familyの偏りとTRAIN/DEVの関係を記録する。
6. 学習に使う異なるAssistant応答は5万〜10万件程度を準備目安とし、候補側は合計100万教師tokensをなるべく1巡で供給できる幅を目指す。これは準備済み量でも、達成保証でもない。量が足りなければ水増しせず、学習開始前に量と配合の提案を改訂する。
7. 新しく選んだ教材を、source・長さ・単発/複数turn・話題で層化して300件内容確認する。重大な教師誤りを直してからTRAINを凍結する。標本確認を全件の意味品質保証にしない。

成果物は出典付きTRAIN、除外理由、異なる会話/応答/family数、本文bytes、Assistant教師量、EOT割合、重複率、QA記録、manifest。複数turn・訂正・条件参照の有効例がどれだけ存在するかも数える。今回の素材で不足する能力は不足として残し、人工テンプレートを黙って追加しない。

## 8. 時間と作業順

ローカルGPUの累積利用時間に上限はない。旧4800秒等の残額で今回を止める扱いには戻さない。一方、各runの100万教師上限、実測に基づくタイムアウト、無更新・非有限値・破損時の異常停止は実行前に固定する。CPU準備/内容確認とGPU秒を別記し、過去の消費記録は消さない。

過去の本SFTは約190万教師で学習部分約17〜25分だった。今回の2腕計約200万教師は、**学習部分20〜60分程度を仮の目安**とする。新しい履歴長・受入分布・速度計測で見積り直し、教材整備・2,190応答の生成/内容確認・保持/保存は別に見積もる。初回比較全体がこの時間で終わるという約束ではない。

進める順序は、**教材棚卸し・選別 → TRAIN/DEV・比較契約固定 → 必要な実装/実機確認 → 2条件のSFT → 全内容比較 → 新候補をUIで試す/結果報告**。今回はこの計画の保存まで。最初の実作業は、公開教材の採用可能量と既存保留IDを確認し、候補のデータ仕様を具体化すること。
