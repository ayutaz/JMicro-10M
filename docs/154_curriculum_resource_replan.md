# 主SFT前の時間計画の訂正

2026-10-17。計画153の最初の技術wrapper（config `35c14f6f`）は、対照の技術16更新後、全16更新中の最大実測から見積もった1M教師の所要4,882.053283秒が事前3,600秒を超えたため停止した。本学習0、候補の技術確認0、品質未評価。旧wrapper・config・process・失敗・予測を閉鎖したまま保全する。終了時までのGPU stage wall5.505592秒を全額持ち越す。

累積ローカルGPU利用に上限を設けないという既存のユーザー指示を用い、**こちらで置いた時間計画だけを、本学習前に明示的に訂正する**。これは科学的品質改善の結果でも、元の3,600秒条件を満たしたという主張でもない。151/153の主SFT各3,600秒という実行計画を、別のresource-v2で各7,200秒へ改める。他の教師量1M/腕、教材・配合・両腕共通LR1e-4・seed42・元Base/fresh Adam・数式・精度・最大shape・32生成・全2,628内容評価・採否基準は変更しない。旧条件の予測を外れ値除外や再計時で短く置換しない。

旧対照のCPU全消費は3,048 microbatch、候補は3,901。旧対照予測から300秒の保存等枠を分離し、同じ最大実測率で候補を外挿すると約6,164.37秒となる。両腕7,200秒はこの費用と同じ300秒枠を上回る有限な割当として、次の実行前に設定する。新しい技術確認は両データ経路・全state保存再開・全32計時を改めて検証するが、旧4,882.053283秒を消さず、新しい計時から旧条件の成立を宣言しない。

最初のwrapperはforecastのassertより後にtimingを保存する構造だったため、16更新の個別timingは永続化されていない。例外内の実予測・16更新到達heartbeat・実stage時間は残るが、どの更新が最大だったかは未確定。resource-v2ではstepの返却直後に全技術履歴を追記保存し、次のassertが失敗しても原timingを残す。数値学習器はそのまま使い、保存observerの時間もstage wallへ算入する。

新wrapper/config/launcherは別名にし、旧失敗processの実不在とBase UIの復帰を確認してから実行する。技術600秒は旧5.505592秒込みで残594.494408秒。評価枠10,800秒は保持する。新しい有限枠でも不成立なら、その条件で停止して原結果を残す。失敗した旧entryを再開可能な中断へ書き換えない。
