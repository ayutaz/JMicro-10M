## 次の比較は教材recipeを一つ変える

第一候補は、**意味構造と自然な質問の多様性を増やした新しいTRAIN版**。比較対照は最新のD1とし、同じ元WebUI10B親からfresh optimizerで学習する候補を最大1件にする。D0は過去の参考値として保存し、見たDEVで都合のよい対照や中間checkpointを選び直さない。

D1からの変更は教材recipe全体だけ。LR・教師予算・Tokenizer・構成・padding・decode条件は同時に変えない。複数の教材要素をまとめて変えるため、個別要素の因果効果とは呼ばない。旧D1のTRAIN・親・seed・schedule・全stateの一致を証明できれば、対照checkpointを再利用する。新学習や独立seedの実績には数えず、新しい未使用DEVで対照も評価する。

この提案を支持しない結果が出た場合は、一巡を閉じて報告・停止する。次の教材、LR探索、追加周回、Base復旧を自動で連続実行しない。Base復旧を選ぶ場合は[計画124](124_base_recovery_plan.md)へ分岐し、証拠を満たしたBaseで通知・停止する。

## 教材と評価を準備する仕様案

以下は再開後に作成する成果物の仕様で、現在の準備完了を意味しない。

- TRAINの各familyに要求情報、最新の事実、否定・許可、話者、更新順、正解根拠を記録する。事実が足りない例には必要な点だけの聞き返しを教師にし、明確な質問には具体的に回答する。
- 意味familyは単なる人名・数値の置換で水増ししない。独立した場面、条件の関係、質問順、自然な言い換え、適切な回答形式を補う。対となる条件変更例と同じ生成元は同じTRAIN familyへまとめる。
- QAは根拠との整合、助数詞、否定、話者、未提示事実の創作、自然さ、Assistant役割を確認する。family数・生成元・本文/EOT教師量・応答長・first-turn比率・再使用量を保存する。sample確認を全TRAINの認証へ読み替えない。
- TRAIN実体とQAを凍結してから、未使用の意味familyによる新DEV80と自己生成24会話59turnを固定する。既知の新DEV80と旧DEV80は両方とも回帰評価へ残す。見たDEVの文章・具体的誤答・正解をTRAINへ移さず、protectedTESTには触れない。
- 原文hash、生成元/family/split、近似重複と既知評価への混入、教師mask・消費契約を確認する。既存全corpusやTokenizerの再構築は行わない。独立人間のQAがない場合は、その限界を記録する。

## 回復・効率・最終確認は条件を分ける

今回の回復predicateは[凍結config](../configs/phase7/chat-generalization-20261013.json)の必要条件をすべて満たせず、not_triggeredとして閉じた。新比較で回復を提案する場合も、最終の新DEVと既知2suiteすべての内容≥56/80、対応する正しい提供履歴の文脈≥15/24、登録機械gate、未使用新内容の対照比改善、自己生成に文脈2未満が残ることを先に確認する。自己生成文脈が15/24を通っても誤りは残り得る。TRAIN由来の誤Assistant履歴からの回復20%置換は別の同B/fresh optimizer比較として提案し、DEV誤答を教材へコピーしない。現在は未実行・効果未確認。

paddingは最初の比較で変えない。終了済みの数値不一致を事後の許容差拡大で救済しない。新方式を検討するなら教師列/位置/mask/更新group/LR、loss/勾配/重み、全state保存再開と速度/VRAMを独立contractで登録する。今の24確認更新を繰り返すことを既定作業にしない。

有望recipeに独立学習seed43、人間blind、fullDEV、最終継続suite、選定封印後のprotectedTESTと正式採否が必要。これらは後続の別段階で、初回seed42やsamplingの3生成seedでは代用できない。Base/Chat採用・量子化・配布・公開へ自動移行しない。
